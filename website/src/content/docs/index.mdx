## What is binpatch?

`binpatch` is a small, well-typed library that **applies** binary delta patches
in the [TRDIFF10](https://github.com/getsentry/cli) wire format, plus a thin
**discovery** layer for locating patch chains in OCI registries or GitHub
Releases, plus a **GitHub Action** that publishes them. It is the public,
extracted core of the upgrade system used by the [`sentry-cli`](https://github.com/getsentry/cli)
and [`@loreai/gateway`](https://www.npmjs.com/package/@loreai/gateway) binaries.

You ship a 287 MB binary. A new release only changes a few hundred KB.
Without deltas every user pays for the full download. With `binpatch`,
each user downloads a 188 KB patch and your apply logic — patch chain
discovery, integrity verification, OOM guarding, progress reporting —
already wired up.

## When to use binpatch

Use it when you ship a self-updating binary and want to:

- **Save your users bandwidth.** A 287 MB binary whose typical update
  changes ~0.07% should not require a full re-download.
- **Skip writing a discovery protocol yourself.** Plug in `ghcrSource()`
  for nightly, `githubReleaseSource()` for stable — both resolve patch
  chains against a target version.
- **Match the wire format of a sister tool.** TRDIFF10 is what
  [`sentry-cli`](https://github.com/getsentry/cli) and
  [`@loreai/gateway`](https://www.npmjs.com/package/@loreai/gateway) speak.

Do **not** use it when:

- Your updates are source-level (use git, `npm update`, etc.).
- You can ship a small binary — deltas only amortize at >50 MB or so.
- You need a Courgette-style executable-aware diff (this is plain bsdiff;
  see the [Architecture page](./architecture/#why-not-courgette-style-executable-aware-diff)
  for why).
